# Architecture

The manual frontend safely loads YAML/JSON into strict Pydantic models. The optional
provider-neutral LLM frontend requests a `Document`, validates it, requires quoted provenance
spans, verifies their source identity, bounds, and exact source substrings, feeds validation errors
back for bounded retries, and never returns surface prose. The packaged offline replay frontend
first binds a versioned gold proposal to the complete source SHA-256, then passes it through that
same boundary for credential-free end-to-end reproduction. It is identified as `offline-replay`
and does not claim to perform extraction.

The IR explicitly represents actors, actions, referents, conditions/exceptions, negation, before/after relations, quantities/units/tolerances, hazards, provenance, references, causal links, and unresolved ambiguity. Section kinds distinguish procedure, description, warning, caution, and note.

The deterministic realizer composes clauses and records the complete source-node feature snapshot for every sentence. Causal relations have unique IDs, source spans, distinct statement endpoints, and unique directed endpoint pairs. They realize as one explicit labeled sentence, `Cause: <cause clause>; effect: <effect clause>.`, after their endpoint statements. Semantic validation independently reconstructs that sentence from the two primary statement mappings and verifies its relation mapping, direction, and feature snapshot. Lexical validation classifies canonical terminology before individual words, then accepts general words, units, numbers, and punctuation. Terminology matching uses full Unicode case folding and maps folded matches back to complete original character spans, so expansions such as `ß` to `ss` preserve correct boundaries and diagnostic offsets. Symbolization and lexical validation share one configured-unit boundary policy: unit surfaces can directly follow or precede numbers, while adjacent Unicode letters or underscores prevent substring matches inside alphabetic words. Structural checks are deliberately small STE-inspired heuristics. Semantic checks use mappings plus independent text checks for high-risk features. Metadata is not enough for an untrusted neural backend: it must create a mapping that an independent aligner verifies. The parser-free CLI aligner grants mappings only to position-preserving exact matches of deterministic controlled sentences; changed, omitted, reordered, and extra sentences remain unmapped and are rejected.

Terminology and vocabulary resources fail validation before indexing when their symbolic ownership would be ambiguous. Terminology IDs are unique; canonical forms and aliases have one case-insensitive owner; deprecated replacement references exist and are acyclic. Vocabulary lemmas and inflections use the lexicalizer's ASCII word grammar and have one case-insensitive owner. Term, alias, and unit surfaces are stripped and nonblank. Numeric-only term and unit surfaces are rejected because numbers have their own `NUMBER_*` symbol class. Quantity values and tolerances must be finite. These restrictions make surface-to-symbol classification independent of resource order and keep exported canonical JSON standards-compliant.

## Constrained neural design

1. **Encoder-decoder:** `TransformersEncoderDecoderSymbolGenerator` encodes canonical JSON IR and decodes a symbolic sentence plan with an immutable model identity: a model ID plus a full lowercase 40-character commit digest. Both the revision-qualified model ID and the exact digest are retained in realization metadata. Its tokenizer-level prefix constraint permits only exact tokenizer round trips of the request allowlist separated by spaces and explicit EOS termination; non-padding tokens after EOS are rejected, and the decoded symbols are checked again. Loading is lazy and optional. This is an inference boundary, not a shipped checkpoint or quality claim; task-specific training and evaluation remain future work.
2. **Decoder-only + LoRA:** place canonical IR before the symbolic plan. Existing small models and adapters are convenient, but prompt handling and unsupported continuations increase risk.

Both must emit from a grammar of symbolic word, term, unit, punctuation, whitespace, newline, and number IDs. Current plans begin with `PLAN_EXACT_WHITESPACE_V1`: lexicalization concatenates their surface tokens and adds whitespace only for `SPACE`, opaque Unicode `WS_U*`, and `NEWLINE` symbols, so both spaced punctuation and adjacency are lossless. Exact `WORD_*` symbols percent-encode the observed approved word surface and reproduce its casing without implicit sentence capitalization, including after internal punctuation. Exact term symbols have the whitespace-free form `TERM_<escaped-id>|<escaped-observed-surface>`; percent-encoding makes the delimiter unambiguous inside both fields. The allowlist is enforced before either field is decoded, then the identity must resolve to an approved term and the observed surface must casefold-match that term's canonical form. Exact lexicalization emits the observed surface. Markerless legacy plans retain conventional implicit spacing, canonical vocabulary and term spelling, and optional sentence capitalization for direct backward-compatible lexicalizer use. Neural inference rejects any generated plan whose first symbol is not `PLAN_EXACT_WHITESPACE_V1`, so legacy casing behavior cannot cross the neural trust boundary. Named common punctuation and opaque Unicode `PUNCT_U*` IDs cover every punctuation mark accepted by lexical validation. Punctuation inside copied terms and units never changes casing. `plan-symbols` creates one deterministic training target. `export-symbolic-corpus` sorts source paths, writes canonical JSONL, rejects duplicate document IDs and symlinked IR inputs, validates claimed metadata against the loaded deterministic realizer, resources, and validation-pipeline profile, and records the exact corpus SHA-256 plus verified metadata profiles in a manifest. It fsyncs both files in an immutable content-addressed generation directory before atomically switching one `current` selector. `read_symbolic_corpus` reads that selector once, opens the selected generation directory, and then reads both artifacts relative to the pinned directory descriptor; a concurrent selector switch therefore cannot mix generations. Complete prior generations remain available to already-pinned readers. Output subtrees nested within the source are excluded without suppressing inputs when the output is a sibling or ancestor. At inference, `NeuralRealizer` supplies only the symbols present in the document's deterministic reference plan, including its format marker; this prevents invented words and quantities without trusting model metadata. `SymbolicLexicalizer` rejects out-of-plan symbols and copies authorized word and term surfaces plus configured units. Whitespace-layout metadata is reported independently, but deterministic IR mappings are inherited only when generated controlled text exactly equals the deterministic surface; casefold-equivalent swaps cannot regain trust. The independent surface aligner then grants IR mappings only to exact generated output, so reordering, omission, or any surface change fails semantic validation.

A prefix trie or character-level finite-state machine can constrain symbol syntax in a concrete model adapter. Naive BPE masking cannot reliably express word boundaries because approved strings and model tokens are not one-to-one. The deterministic validator remains authoritative; LoRA changes probabilities, not guarantees.

See [ADR 0002](adr/0002-encoder-decoder-symbol-generator.md) for the encoder-decoder adapter's exact trust boundary and current limitations.

The decoder-only LoRA adapter implements the token-grammar option with Hub-only base and adapter
identities pinned by full lowercase 40-character commit digests. Both exact digests are retained
separately in metadata alongside the revision-qualified model ID. Generation is explicitly
sanitized, greedy, and single-example; inherited minimum-length settings are reset so EOS remains
available at every valid symbol boundary. Output is accepted only as one batch of integer token IDs
with explicit EOS termination and a lossless tokenizer round-trip check for every allowed symbol
form. The complete raw pre-EOS path is replayed through the token grammar before special-token
skipping or text-level allowlist checks.
The loader requires safetensors, resolves and reuses one checked adapter snapshot, validates the
pinned adapter as LoRA for the exact configured causal LM commit, and lazy-loads Transformers and
PEFT only when the adapter is constructed without injected test doubles. See
[ADR 0002](adr/0002-decoder-only-lora-symbol-generator.md). No trained adapter or comparative
result ships with this implementation.

## Trust and reproducibility

Source, YAML, glossary data, and model output are untrusted. There is no template execution or shell interpolation. Version metadata travels with every realization. Tests make no network calls. Current limitations include heuristic POS/voice analysis, no full discourse planner, and metadata-assisted rather than parser-backed semantic alignment.
